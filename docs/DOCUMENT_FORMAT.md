# Формат документа SOPR

Новые документы сохраняются как UTF-8 JSON с расширением `.sopr.json`.
В обычном пользовательском сценарии изображение служит ключом, а документ
лежит рядом в скрытом каталоге `.save`. Само изображение не содержит состояние
внутри своих PNG/JPEG-данных.

Минимальная структура:

```json
{
  "format": "sopr-scheme-document",
  "version": 1,
  "task_type": "beams",
  "canvas": {"width": 400, "height": 250},
  "common": {},
  "settings": {},
  "text": "",
  "task": {
    "version": 1,
    "payload": {}
  },
  "extensions": {}
}
```

- `format` и `version` задают общий формат файла.
- `task_type` — стабильный ID из реестра типов, а не локализованный заголовок.
- `canvas`, `common`, `settings` и `text` содержат состояние интерфейса.
- `task.version` версионирует модель конкретного типа независимо от envelope.
- `task.payload` содержит модель задачи.
- `extensions.section` сохраняет редактор поперечного сечения там, где он есть.
- Опциональный `extensions.page_layout` версии 1 хранит независимые
  `task_frame` и `note_frame` (`x`, `y`, `width`, `height`) в пикселях листа.
  Его отсутствие включает исторический путь компоновки без миграции координат.

## Модель и безопасность

Payload поддерживает JSON-значения и несколько внутренних маркеров:

- `$type: object` — экземпляр модельного класса из allowlist выбранного типа;
- `$type: tuple` — кортеж;
- `$type: ndarray` — числовой NumPy-массив;
- `$ref` — ссылка на другой объект внутри того же payload.

Имена Python-модулей в файл не записываются и из файла не импортируются.
Каждый stable task ID имеет явный список допустимых классов и отдельную таблицу
миграций. Неизвестная версия, класс, ссылка, настройка или тип значения
отклоняются до переключения активного документа. Размер входного файла
ограничен 10 MiB, а размер холста — 10000×10000.

Запись выполняется через временный файл в том же каталоге с последующим
атомарным `replace`.

## Работа в приложении

В меню File действует image-first workflow:

- **Открыть схему…** — выбирает PNG/JPEG и ищет состояние в соседнем `.save`
  по SHA-256 картинки; прямое открытие JSON и `.dat` также поддерживается;
- **Сохранить схему…** — создаёт PNG/JPEG и
  `.save/<sha256>.sopr.json`;
- **Экспортировать изображение…** — создаёт PNG/JPEG без нового sidecar;
- **Импортировать старый .dat…** — прямой legacy-import.

При открытии старой картинки приложение сначала ищет JSON, затем исторические
`.save/<sha256>.dat` и `.save/<имя-картинки>.dat`. Найденный `.dat`
загружается и сразу записывается как хешированный JSON-sidecar.
